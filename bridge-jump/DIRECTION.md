# ワンタップ・ジャンプ橋 ディレクション記録

Grok Bot（ゲームディレクター）が Gemini 3.8 Flash（Antigravity CLI）に送った指示を、各回そのまま記録します。

## 初回制作

### 初回制作：初版の実装（原文）

**狙い:** 縦持ち・親指1本の「長押しで棒を伸ばし、離して橋を架ける」核の手触りを1ファイルで作る。最重要はテンポ：倒れる→渡る→次の足場までを素早くつなぎ、止まらずに何度も連続で架け続けられるようにする。赤い中央印のPERFECTとコンボで上手さが報われる構造を最初から入れ、テスト用に `?bot=1` の自動プレイも用意する。

```
カレントディレクトリからの相対パスで、単一の自己完結ファイル bridge-jump/index.html を作成してください（canvas + vanilla JS、外部アセット・フォント・ライブラリ・ネットワーク通信なし。404が出ないようにインラインSVGのdata-URIファビコンを入れる）。ブラウザミニゲーム「ワンタップ・ジャンプ橋」、UIテキストは日本語。他のフォルダは触らない。git commit/push はしない。
設計ターゲット: 縦持ちスマホ・親指1本（メインのテストサイズは 390x844）。PC（マウス長押し / Spaceキー長押し）と横持ち（縦長のプレイ列を中央に置き、左右はレターボックス）でも遊べること。
最重要コンセプト: テンポ。待ち時間を最小にして、何度も連続で橋を架け続ける気持ちよさを作る。棒が倒れる・渡る・カメラが次へ進むまでを素早く（1回の成功サイクルが入力後およそ0.8秒以内）、次の足場は渡り終わる前にもう見えている／すぐスライドインする。渡り終わった瞬間から次の長押しを受け付ける。
コア:
- devicePixelRatio対応のレスポンシブ全画面canvas。入力: pointerdown/pointerup（どこでも、preventDefault、二重発火なし、スクロール/ズーム/長押しメニュー無効）、マウス、Spaceの押下/離し。
- 画面下部に足場（柱）が並ぶ横スクロール。今いる足場と次の足場があり、間隔と幅は毎回ランダム（序盤はやさしめ、進むほど幅が狭く間隔が広くばらつく）。足場の上端は親指で隠れない高さ（画面の下から35〜40%あたり）。
- 長押し中、棒人間が立つ足場の右端から棒がまっすぐ上に伸びる（一定速度）。離すと棒が右へ倒れる（回転アニメ、着地で小さな衝撃）。
- 棒の先端が次の足場の上に乗れば成功: 棒人間が棒の上を走って渡り、次の足場の右端付近で止まる。カメラは素早く滑らかにスクロールして、新しい足場が「今いる足場」の位置に来る。新しい「次の足場」がすぐ出る。
- 各足場の上面中央に小さな赤い印。棒の先端が赤い印に入ればPERFECT: 「PERFECT!」表示・フラッシュ、コンボ+1、ボーナス点（コンボに応じて増える）。印を外すとコンボはリセット。
- 短すぎ（届かない）または長すぎ（足場を越える）なら、棒人間は棒の先端まで走ってから落下（棒も回転して落ちる）→ゲームオーバー。
- スコア: 渡った足場の数 + PERFECTボーナス。ベストはlocalStorage（キー 'bridgeJumpBest'）。HUD: 上部中央に大きな現在スコア、小さくベスト、コンボ。
- タイトル画面: 「ワンタップ・ジャンプ橋」「長押しでスタート」(タップでもOK)、1行の遊び方。ゲームオーバー画面: スコア、ベスト、NEW BEST!、「タップでリトライ」。ゲームオーバー後0.5秒だけ入力を無視し、その後はワンタップで即リトライ（タイトルに戻らず即プレイ開始）。
- 短いWebAudio効果音（棒が伸びる間の上昇音、倒れる音、成功、PERFECT（コンボで音程上昇）、落下）と小さなミュートボタン（localStorageに保存）。AudioContextは最初の操作で作成。
- requestAnimationFrame、deltaTimeはクランプ。コンソールエラーなし。
- テスト用フック: window.__game = {state:'title'|'play'|'over', score, best, combo, count(渡った数)} を常に更新。URLに ?bot=1 があるときは自動プレイ: 必要な長さを計算して長押しし、小さなランダム誤差を加える（たまにPERFECT、たまにGOOD）。進むほど誤差が大きくなり、だいたい15〜50回で失敗するようにする。タイトルから自動で開始し、ゲームオーバー後は2秒待ってリトライ。
最後に作ったものを簡潔にまとめてください。
```

## バグ修正（初回制作のあと）

**狙い:** 初版のヘッドレス確認（390×844縦／960×600 PC／844×390横）で見つかった、角丸描画のコンソールエラー・テスト用フックの状態ずれ・自動プレイが失敗しにくい問題を直す。

```
bridge-jump/index.html のバグ修正をしてください。新機能は追加しないでください。他のフォルダは触らない、git commit/push はしない。ブラウザを起動して自分でテストする必要はありません（こちらでヘッドレス確認します）。
1. コンソールエラー: 「Failed to execute 'arcTo' on 'CanvasRenderingContext2D': 5 arguments required, but only 4 present.」がプレイ中に出る（390x844 縦・960x600 PC・844x390 横すべて）。角丸矩形のフォールバック描画など arcTo の呼び出しをすべて正しい5引数にする（または ctx.roundRect がある場合はそれを使う）。
2. テスト用フック window.__game がずれる: 画面に GAME OVER が出ているのに __game.state が 'play' のまま、ベストやスコアも古いことがある。状態・スコア・ベスト・コンボ・count が変わるたび（または毎フレーム）必ず window.__game を更新する。
3. 自動プレイ(?bot=1)が縦持ちで28回以上連続成功して失敗しないことがある。前回の指示どおり、だいたい15〜50回で失敗するように、回数が増えるほど誤差が大きくなる確率を上げる（テスト用なので最終的に必ず失敗するように）。ゲームオーバー後は結果を2秒見せてからリトライ。
コンソールエラー0になるようにしてください。最後に修正点を簡潔にまとめて。
```

結果: 角丸描画の arcTo エラーが解消してコンソールエラー0（縦・PC・横）、自動プレイはおよそ20〜31回でゲームオーバーになるように。

## バグ修正（ブラッシュアップ第2回のあと）

**狙い:** 第2回の確認で見つかった、判定ポップ2行目のはみ出し・倍率の掛け算によるスコアのインフレ・ラッシュ時間のずれを直す。

```
bridge-jump/index.html のバグ修正をしてください。新機能は追加しないでください。他のフォルダは触らない、git commit/push はしない。ブラウザを起動して自分でテストする必要はありません（こちらでヘッドレス確認します）。
1. 判定ポップの2行目が画面からはみ出す: 「+.. (COMBO x15) ≫遠距離+2 🔥2倍!」のような長い行が 390x844 縦で左端から切れて読めない。2行目は内訳を短くし（例「+32 (x15) 遠距離+2 ×2」）、それでも長い場合は2行に折り返すかフォントを縮め、テキスト全体が必ず画面内に収まるようにクランプする。
2. スコアのインフレ: 18本渡っただけで434点、38本で681点になり、コンボ倍率×ラッシュ2倍×足場ボーナスが掛け算で膨らみすぎてベストの比較が分かりにくい。PERFECTのコンボボーナスは +2×コンボ で上限 +10、ラッシュ2倍は基本点とPERFECTボーナスのみに掛けるように整理し、目安として30本で200〜300点程度に収める。
3. ラッシュの残り時間表示が 6.8s など指示（5秒）より長く始まる。ラッシュは5秒きっかりで、表示と実際の効果時間を一致させる。
```
