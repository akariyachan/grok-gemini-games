# 猫の手も借りたい — DIRECTION

実装: **agy（Antigravity CLI / Gemini 3.8 Flash, `--model gemini-3.8-flash-high`）**。企画・指示: Grok Bot。画像: Grok Bot の画像生成（assets/）。

## Round 0（初回制作）— Grok Bot → agy への指示原文

```
このフォルダ（neko-no-te/）に、縦持ちスマホ向けブラウザゲーム「猫の手も借りたい」を単一ファイル neko-no-te/index.html（HTML/CSS/JS、外部ライブラリ・外部フォント・ネットワーク通信なし。404が出ないようにインラインSVGのdata-URIファビコンを入れる）で作ってください。日本語UI。他のフォルダは触らない。git commit/push はしない。

【概要】人手不足の食堂。気まぐれな猫の店員たちが次々に出勤してくる。プレイヤーは店長で、待機中の猫を指でフリック（ドラッグして放す）して厨房の持ち場に投げ入れ、届く注文を時間内に仕上げる。猫はサボる・寝る・性格がバラバラ。その「クセ」をうまく使うのが面白さの核。

【画面（390x844 縦が基準）】
- 上部: HUD（ステージ名・残り時間・売上/目標・評判★）と、注文チケットの列（最大3枚。料理の絵、必要な工程アイコン、待ち時間ゲージ。ゲージが尽きると客が怒って帰り評判-1）。
- 中央: 厨房。4つの持ち場を2x2で配置：「切る」「焼く」「盛る」「運ぶ」。各持ち場は猫を1匹まで入れられ、作業中の進捗ゲージと猫の状態（作業中/サボり💤/寝てる/やる気MAX）を表示。
- 下部: 猫の待機場（休憩マット）。最大4匹の猫が並ぶ。ここから持ち場へフリック。持ち場の猫を待機場や別の持ち場へフリックし直すこともできる。
- 844x390 の横画面でも崩れない（縦長のプレイ領域を中央に、左右は背景）。PC はマウスドラッグで操作可能。

【注文と工程】料理ごとに必要工程の順番が決まっている。例：焼き魚（切る→焼く→運ぶ）、オムライス（焼く→盛る→運ぶ）、寿司（切る→盛る→運ぶ）、ラーメン（切る→焼く→盛る→運ぶ）、パンケーキ（焼く→盛る→運ぶ）。注文は先頭の未完了工程から順に処理され、その持ち場に猫がいれば自動で進む（工程が終わると次の工程の持ち場へ自動で回る）。「運ぶ」が終わると提供完了：売上＋（早いほどチップ）。

【猫（性格とクセ）】assets/ の絵を使う。それぞれ数値（速さ・サボり率・得意持ち場）と特殊なクセを持つ：
- トラ（cat_tora）: 速いが飽きっぽい。同じ持ち場に8秒いるとサボり始める→フリックで持ち場を替えると復活。
- ハカセ（cat_hakase）: 遅いが丁寧。「切る」が得意で、ハカセが切った料理はチップ2倍。
- シロ（cat_shiro）: 眠り猫。ときどき寝る。寝ている猫をタップ連打で起こせる。「運ぶ」に置くと寝ながらでも少しずつ運ぶ（なぜか）。
- クロ（cat_kuro）: 「焼く」の名人だが、隣の持ち場に猫がいると張り合って速くなり、誰もいないとやる気が落ちる。
- ミケ（cat_mike）: 新人で超元気。どこでも普通の速さだが、ときどき勝手に別の持ち場に飛び移る。
- 料理長（cat_boss）: ボス。最終ステージにだけ現れる見回り役で、サボっている猫を見つけると評判が下がる（その前に起こす/持ち場替えする）。
猫の状態はアイコンと吹き出しのひとこと（「にゃ…飽きた」「Zzz」「負けないにゃ！」等）で分かるように。フリックで投げると放物線で飛んで持ち場に着地する気持ちいい演出。

【ステージ】全5ステージのステージクリア型（1日営業＝90秒前後）：1 朝の定食屋（トラ・ハカセ、焼き魚と寿司のみ、ゆっくり）／2 昼のランチラッシュ（シロ追加、オムライス追加）／3 夜の居酒屋（クロ追加、ラーメン追加、注文が速い）／4 雨の日の大混雑（ミケ追加、パンケーキ追加、注文が同時に来る）／5 料理長の視察（料理長の見回りつき、全料理）。目標売上に届けばクリア（★1〜3）、届かないか評判0でやり直し。ステージ選択（クリア済み解放、localStorage 'nekoNoTeProgress' に保存）とクリア画面（売上・提供数・各猫のMVPひとこと）。
タイトル画面: 猫たちのイラストと看板風ロゴ、「営業開始」ボタン、1行の遊び方。

【素材】assets/ の画像を必ず使う（すべて .jpg、クリーム色背景）：猫 cat_tora, cat_hakase, cat_shiro, cat_kuro, cat_mike, cat_boss（384px正方形）、料理 dish_fish, dish_omurice, dish_sushi, dish_ramen, dish_pancake（384px）、背景 bg_kitchen（576x1024、縦長の厨房）。猫は丸く切り抜いて表示してよい（border-radius）。
【その他】WebAudio の短い効果音（フリック、着地、工程完了、提供チャリン、客が怒る、ステージクリア）と小さなミュートボタン（localStorage）。AudioContext は最初の操作で作成。requestAnimationFrame、deltaTimeはクランプ。スクロール・ズーム・長押しメニュー無効。コンソールエラーを出さないこと。
【テスト用】window.__game = {state:'title'|'play'|'clear'|'fail', stage, sales, target, served, angry, rep} を常に更新。URLに ?bot=1 があれば自動プレイ：タイトルから自動で開始し、空いている持ち場や必要な持ち場に待機中の猫を（フリックと同じ関数で）移動、寝ている猫は起こし、サボった猫は持ち場替えする。だいたい7割くらいの出来でステージを順に進め、クリア/失敗画面は2秒見せて次へ（失敗ならリトライ）。

【作業の進め方】大きなファイルを一度に書くと止まりやすいので、まず骨格を書き、その後データ・ロジック・描画・演出を小分けに追記/編集してください。完成したら node 等でスクリプト部分の構文チェックをし、最後に変更点の要約を出力して終了。git commit はしないでください。
```
