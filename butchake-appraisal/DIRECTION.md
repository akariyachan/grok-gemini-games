# ぶっちゃけ鑑定所 — DIRECTION

実装: **grok-4.7（Grok Build CLI `grok`）**。企画・指示: Grok Bot。画像: Grok Bot の画像生成（assets/）。

## Round 0（初回制作）— Grok Bot → grok への指示原文

```
このフォルダ（butchake-appraisal/）に、縦持ちスマホ向けブラウザゲーム「ぶっちゃけ鑑定所」を単一ファイル index.html（HTML/CSS/JS、外部ライブラリなし）で作ってください。日本語UI。

【概要】プレイヤーは辛口AI鑑定士。お客さんが品物を持ち込み「これ本物ですか？」と聞く。カードを右スワイプ＝本物、左スワイプ＝ニセモノで即決（ボタンでも可、キーボード←→も可）。
【判断の根拠（3種）】
(1) 品物の手がかり：品物画像の上にコードで（Canvas/SVG/CSS）小さな違和感を描いて重ねる。例：江戸時代の壺の裏にバーコード、ピカソの絵のサインが「Picaso」、月の石に値札シール「¥980」、懐中時計に「MADE IN 2019」刻印、刀に「おもちゃ」シール等。画像そのものに手がかりは入っていないので必ずコードで描くこと。品物を長押し（またはダブルタップ）で拡大ルーペ表示して細部を調べられる。
(2) 客の自己申告の矛盾：吹き出しのセリフ（例「祖父が100年前に買いました」）と品物の説明札（例「製造：1975年」）を見比べて矛盾を見つける。
(3) 怪しいそぶり：客の絵の上に汗・目が泳ぐ（絵を左右に揺らす）・早口（吹き出しが高速表示）などの演出。ただし正直だが緊張しているだけの客（汗をかくが本物）のひっかけも混ぜる。
本物の品は手がかりなし・矛盾なし（またはそれっぽいが問題ない細部）。
【種明かし】判定後に必ずGrok鑑定士の辛口一言を出す（例「バーコード付きの江戸時代、斬新ですね」「緊張してただけの正直者を疑うとは、私も人のこと言えませんね」）。正解・不正解どちらも笑えるように。どの手がかりが根拠だったかをハイライト表示。
【ステージ】全5ステージのステージクリア型：1 町の骨董市 / 2 質屋 / 3 美術オークション / 4 宇宙の密輸品 / 5 最後の大鑑定（ボス客：cust_boss）。各ステージ客8人前後、規定正解数（例6/8）でクリア、未達ならリトライ。ステージが進むほど手がかりが小さく薄く、ひっかけ（本物なのに怪しく見える）が増え、制限時間（1人あたりのタイマー）が短くなる。ステージ選択（クリア済み解放、localStorage保存）とクリア画面。品物・客・手がかり・セリフ・辛口コメントのデータは各ステージ十分な種類（全体で40件以上）を用意。
【素材】assets/ にある画像を必ず使う：客 cust_grandpa, cust_madam, cust_salaryman, cust_shady, cust_alien, cust_boss（.jpg、384px正方形、クリーム背景）、品物 item_vase, item_painting, item_moonrock, item_watch, item_katana, item_crystal, item_crown, item_daruma（.jpg、白背景）。品物画像は丸角カード内に表示し、白背景が馴染むように。
【画面】390x844 の縦画面で全要素が収まること（844x390 の横画面でも崩れない）。上に客の絵＋吹き出し、中央に品物カード＋説明札、下に「← ニセモノ / 本物 →」。HUD：ステージ名・残り客・正解数・タイマー。効果音はWebAudioで簡単に。
【テスト用】URLに ?bot=1 があれば自動プレイ（正解を7割程度で選んで自動で進み、ステージを順に進める）。window.__game にステート（stage, correct, served, state 等）を公開。コンソールエラーを出さないこと。

【作業の進め方】大きなファイルを一度に書くと止まりやすいので、まず骨格を書き、その後データ・描画・演出を小分けに追記/編集してください。完成したら node 等で構文チェックし、最後に変更点の要約を出力して終了。git commit はしないでください。
```
